## 二、完整网络链（reload 全量，结论 2）

### 2.1 初始化（取题）
```
GET https://cap.dingxiang-inc.com/api/a
    ?w=380&h=165&s=50
    &ak=<appKey>
```

## 三、提交接口规格（结论 3，核心）

```
POST https://cap.dingxiang-inc.com/api/v1
Content-Type: application/x-www-form-urlencoded
Referer: https://www.dingxiang-inc.com/
User-Agent: <浏览器常规>
```
form 参数（**全集，两次样本完全同构**）：

| 参数 | 样本(drag1) | 样本(drag2) | 含义（推断，含证据） |
|---|---|---|---|
| `ac` | len=1813 | len=1793 | **加密轨迹体**。形态 `5948#<长串>`：`5948#` 前缀 + 单段长串（含 +/%2F/%3D 等 base64 字符与自定义编码）。两次拖动 ac 同前缀不同体 |
| `ak` | 99de95ad1f23597c23b3558d932ded3c | 同 | appKey |
| `c` | 6ac45e92ZNi9AwoH4hzRvN7PogivypXxvRczR8d1 | 同 | constid 设备 token（`/udid/c1` 的 data） |
| `uid` | (空) | (空) | 用户 uid（未登录为空） |
| `jsv` | 5.1.53 | 同 | SDK 版本 |
| `sid` | b4b36be404f9a5bfc1a5d7562349edc4 | d9c9a0f9a9c4c39b8e24c7b2c38e2bb7 | 本题会话 id（来自 /api/a） |
| `aid` | dx-1791254331515-6147815-3 | dx-1791254922626-37899156-3 | 实例 id（来自 /api/a 请求参数） |
| `x` | 240 | 96 | **碎片最终"图内水平位置"**（UI px，相对图左缘）。实测 = 初始槽位 20 + 鼠标拖动 Δ（220→240、76→96，两样本一致） |
| `y` | 73 | 56 | 碎片垂直位置（= /api/a 返回的 y，原样回传） |
| `w` | 380 | 380 | 图宽 |
| `h` | 165 | 165 | 图高 |

响应全集（JSON）：
```json
{"success":false,"token":null,"msg":"请求超时","tp":null,"sv":null,"retry":0,"ot":1}   // drag1：会话超时
{"success":false,"token":null,"msg":"retry","tp":null,"sv":null,"retry":1,"ot":null}  // drag2：距离不对，可重试
```
- 字段：`success` / `token`（成功时应为验证票据）/ `msg`（"retry"=距离不达标；"请求超时"=会话过期）/ `retry`（bool-ish）/ `ot`（超时标记）
- 失败后 UI：短暂显示"验证失败 请按提示重新操作"，滑动条复位（sub-slider 回 x=344），**同一题可继续重试**（题不换）。
- 证据文件：`artifacts/dx-drag1-net.json`、`artifacts/dx-drag2-net.json`、`artifacts/ac-samples.json`（ac 完整样本两条）。

### 缺口视觉定位方法（本次探索结论）
- 碎片/缺口对齐**不能靠内容匹配**（碎片 webp 内容与背景缺口内容 NCC 仅 0.3-0.5），要**靠形状轮廓**：
  - 在**客户端 canvas 渲染图**（用户实际所见）上跑 **Chamfer（碎片 alpha 轮廓 ↔ 背景 Canny 边缘距离变换）**，第 3 题出现强收敛（d≈1.5/点，y 与 api y 精确吻合）；
  - 辅以 **NCC 内容匹配（约束在 y=api y 行带内）**做交叉验证。
  - **p1 原图（服务端提供）上没有"洞"的轮廓**（Chamfer/NCC 均无信号）→ 缺口/干扰是**客户端渲染阶段生成**的（canvas 与 p1 全图差异巨大：NCC<0.4、diff mean>50）。
- 第 2 次实验的定位结论：缺口碎片框左上角 ≈ 原图坐标 x=100-103（Chamfer 100 / NCC 102，y 64-71 与 y_api=56→67.9 吻合）→ 换算 Δ=x*0.95-20≈76。**服务端仍 retry** → 参照点/容差细节尚未对齐（见待办）。

## 五、其他观察

- **七陌客服悬浮窗（`#chatIframe`, fixed 350×500, z-index 巨大）遮挡页面中右部**，导致无法点击验证条；绕过法：把目标元素滚动到视口顶部 y≈160（body.scrollTop 精密调整）后，用 elementFromPoint 多点采样选"未被遮挡的坐标"再真实点击。
- 页面滚动发生在 **body**（`document.body.scrollTop`），视口 1028×861，dpr=1.5。
- SDK 混淆形态：`captcha-ui/v5/index.js`、`oneclick-Captcha-js-5.1.53.js` 为**字符串数组混淆 + Unicode 私用区字符标识符**，明文不可读；`/api/a`、`/api/v1`（另见 /api/v2、/api/v3 字符串）端点在其中。`constid-js`、`greenseer.js` 亦同风格。
- **反调试/DevTools 检测：未观察到主动 debugger 陷阱或页面异常**（本轮全程未开 DevTools 面板；未专门做 DevTools 检测实验——如实标注为"未验证"）。

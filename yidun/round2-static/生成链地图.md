## 3. 加密实现判定（必达：纯 JS 而非 WebCrypto）✅

**判定：100% 纯 JS 自研分组加密**（SDK 内部命名为 `aes`，但**不是**标准 AES-128/256）。
- 无 `window.crypto` / `SubtleCrypto` / `crypto.subtle` 调用；无 CryptoJS；无标准 AES S-box（`0x637c777b` 未出现）。
- 模块结构（webpack）：`#0xa` 加密封装（:2843-3065）、`#0x1a` 字节工具（:4790-4983）、`#0x1b` 常数表（:4986-4993）、`#0x3a` base64（:9435-9690）。

### 3.1 常数（模块 #0x1b）
```
__SBOX__            = 'a7be3f39...5e'   (512 hex = 256 字节置换盒，非 AES 标准 S 盒)
__ROUND_KEY__       = '037606da0296055c'
__SEED_KEY__        = 'fd6a43ae25f74398b61c03c83be37449'   (32 个 ASCII 字符 = 32 字节)
__BASE64_ALPHABET__ = 'MB.CfHUzEeJpsuGkgNwhqiSaI4Fd9L6jYKZAxn1/Vml0c5rbXRP+8tD3QTO2vWyo'
__BASE64_PADDING__  = '7'
```

### 3.2 算法（伪代码，位置：aes :2987-3035 / 轮函数 :2952-2966 / 密钥派生 :2967-2976 / S盒 :2892-2901）
```
bytes = utf8(str)
crc   = genCrc32(bytes)              # 8 个 hex 字符的 ASCII（8 字节）
buf   = bytes || crc
pad   = 64 - len%64 - 4（len%64>60 时用 128-…）; buf ||= 0x00×pad ; buf ||= int32be(len)
iv    = 4 个随机字节
rk    = rep64(SEED_KEY 的 32 个 ASCII 字节) XOR rep64(iv)      # 64 字节
out   = iv ; prev = rk
for block in chunks(buf, 64):
    t = xors(F(block), rk)
    u = shifts(t, prev)              # shifts = 逐字节加法(add)，非移位
    t = xors(u, prev)
    prev = S(S(t))                   # S = 16×16 S 盒替换
    out ||= prev                     # 64 字节密文块
return base64EncodePrivate(out)      # 表 __BASE64_ALPHABET__ / padding '7'

F(block)：按 ROUND_KEY 每 4 个 hex 一段，取 (操作索引, 参数) 依次作用：
    '0376' → op#3  xor, 参数 0x76 起逐字节自增
    '06da' → op#6  加,  参数 toByte(0xda)=-38 起逐字节自减
    '0296' → op#2  加常数 toByte(0x96)=-106
    '055c' → op#5  xor, 参数 0x5c 起逐字节自减
（op 表 :2950 = [passthrough, xor常数, 加常数, xor自增, 加自增, xor自减, 加自减]）
```
- **关键性质：全部运算（异或/模 256 加/S 盒置换）皆为双射 ⇒ 加密完全可逆**，已实现解密器并自检通过。
- 长度守恒：明文 ≤ 60B ⇒ 输出恒为 68B ⇒ **92 个字符**（必然 1 个尾 '7'）。

### 3.3 反调试/环境依赖（复现时需注意）
- `hexToByte` / `hexsToBytes` 通过 `document.getElementById('NECaptchaSafeWindow').contentWindow.parseInt` 取 parseInt（模块 #0x19，:4795-4825）——iframe 隔离，防原生函数被 hook；纯 Node 复现需 mock（或等价替换为普通 parseInt）。

## 8. 建议（面向"协议直打"）

1. **可直接本地构造 data**：算法确定性 + 完全可逆 + 常数硬编码 ⇒ 只要拿到 `/api/v3/get` 的 `token`，即可在本地生成 `d/m/p/f/ext`（用 aes 加密任意自造明文），再 `JSON.stringify` 作为 `data` 参数。
   - 注意 `token` 是参与 `xorEncode` 的密钥，且与 `p`（几何答案）绑定：**p 的百分比必须与后端正确的缺口位置一致**，否则服务端几何校验必失败——这是协议直打的主要硬约束。
2. `cb` 可直接本地生成：`aes(random32_with_vfnv46_inserted)`，无需浏览器环境（纯函数）。
3. `iv=4` 是常量，直接写死。
4. 需复现 `aes()` 时注意：这是纯 JS 自研算法，**不要**用标准 AES 实现替代；参考本目录 `decrypt-verify.js`（含加密所需全部 helper：toByte/xor/xors/加(shifts)/S盒/私有 base64）。
5. 若在 Node 内直接 require SDK 模块：需 mock `window.encodeURIComponent/decodeURIComponent/parseInt` 与 `document.getElementById('NECaptchaSafeWindow')`（见 `extract-crypto.js` 顶部）。
6. 风控对抗建议：轨迹明文（`d`）字段可自由构造，但要贴近真实（`isTrusted=1`、Δms 递增、点间距平滑），`f`/`ext` 的统计值应与 `d` 自洽（如 traceData.length 相同）。
